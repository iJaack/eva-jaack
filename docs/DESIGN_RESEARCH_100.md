# Eva Design Reference Inventory

Purpose: document the web research behind the next Eva visual direction. This is not a mood board to copy. It is a pattern inventory for a product that turns prediction markets and facts into evolving thesis posts.

Research date: 2026-06-06.

## Source Set

- Godly typographic, large-type, minimal, portfolio, and transition collections: typography-forward, editorial, portfolio, and motion-heavy sites.
- Godly.design: real product, app, section, logo, and OG-image examples.
- Landbook: curated website and section library with category, section, mobile-preview, and historical-version filters.
- WebInspoo: SaaS gallery with 1,200+ curated screenshots and structured filters for category, typography, color, and stack.
- SaaSFrame: SaaS flows, dashboards, add/edit screens, account setup, and interface screenshot sequences.
- Saas Interface: app-page and component references, especially builder/editor, dashboard, side panel, item detail, forms, activity feed, and search.
- Awwwards editorial-design material: editorial web foundations around typography, grids, storytelling, art direction, and knowing when to break layout rules.
- Prediction-market and market-terminal references: Polymarket, Kalshi, Manifold, Metaculus, Panther, Spline, Verso, Probity, OpenMarketUI.

## Patterns To Steal, Not Screens To Copy

- Editorial sites win by making typography and rhythm carry the argument, not by surrounding the user with chrome.
- Strong portfolio and studio sites use asymmetry, oversized text, and selective whitespace to create a point of view. Eva currently feels too much like a grid dashboard; it needs more authored hierarchy.
- SaaS editor references converge around a three-part mental model: content canvas, source/sidebar, preview/publish state. Eva should use that model, but avoid generic Notion/Google Docs mimicry.
- Finance and prediction-market references show that probability needs immediate comprehension: one number, one trend, one source, one resolution state. Avoid raw market tables on the writing surface.
- Terminal-style products are useful for density and scanning, but Eva is not a terminal. Terminal density belongs in market search and signal inspection, not in the thesis article itself.
- Mobile product flows hide complexity until needed. On mobile, Eva should default to a focused writing canvas with source drawers, not a three-column squashed desktop page.

## Anti-Patterns Found In Current Eva Compose

- The page splits attention between a left hero block, middle editor, and right source panel; the object of work is not dominant enough.
- The visual system overuses dark terminal cues and grid lines for a product whose core artifact is a public, shareable thesis post.
- Form fields still read like backend DTO inputs instead of a publishing workflow.
- Preview is secondary; it should be first-class because the product object is the post.
- Signals are displayed as small form-adjacent cards; they should behave like source blocks that can be cited, weighted, collapsed, and dropped into the article.
- Publish is too early in the hierarchy. The UX should guide draft, source, preview, validate, publish.
